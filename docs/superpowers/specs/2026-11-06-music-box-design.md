# 八音盒（Music Box）设计文档

日期：2026-11-06
状态：待评审

## 1. 目标

构建一个可在浏览器中观赏的**写实八音盒**，以真实的机械动作展示其工作原理：

1. **发条 / 动力源**：上弦储能，提供旋转动力。
2. **滚筒（音鼓）**：表面分布按曲谱排列的凸点（音钉）。
3. **音板（钢片梳）**：一排长短不一的钢齿，长齿低沉、短齿清脆。
4. **拨动发声**：滚筒旋转时，凸点按时间顺序拨动对应钢齿，奏出旋律。

定位是**观赏作品**：优先写实渲染和好听的声音，讲解只做轻量的悬停标注。

### 成功标准

- 打开页面即可看到光照、材质逼真的木盒八音盒（胡桃木、黄铜、钢、毛毡）。
- 打开盒盖后滚筒开始转动，凸点拨动钢齿的瞬间：该钢齿可见地振动、同时发出对应音高，视听误差 < 1 帧（约 16ms）。
- 可以拖动钥匙上弦，上弦越多播放越久；发条将尽时转速与音乐同步渐慢直至停止。
- 内置 3 首公版曲目 + 1 首应用户要求添加的曲目可切换，切换后滚筒上的凸点重新排布。
- 稳定 60fps（参考机：Apple Silicon Mac，Chrome）。

### 假设与约束

- 运行环境：支持 WebGPU 的桌面浏览器（Chrome / Edge）。不支持时显示提示页，不做 WebGL 回退。
- 曲目：公版古典曲改编（《给爱丽丝》《卡农》片段、《小星星》）；另有《千年等一回》（副歌，非公版，应用户要求添加），不需要编曲功能。
- 渲染基于 vgpu（`vgpu` npm 包）；模型用本机 Blender 5.2.2（`/Applications/Blender.app`）通过 Python 脚本无界面生成。
- 非目标：移动端适配、编曲器、录音采样音色、WebGL 回退、物理精确的弹性仿真。

## 2. 总体架构

```
blender/build_musicbox.py ──(blender -b -P)──> public/musicbox.glb   （静态部件 + 烘焙贴图）

src/
  main.ts            启动：init gpu、加载 glb、组装各模块、frameLoop
  songs/             曲谱数据 + 编曲到钢齿的映射
  mechanism/         机械状态：发条、调速、滚筒角度、拨动事件
  geometry/          程序化几何：钢齿梳、凸点实例
  gltf/              最小 glb 解析器 → vgpu geometry
  render/            vgpu 渲染：PBR、阴影、环境光、拾取、后处理
  audio/             Web Audio 钢齿合成器
  interaction/       相机、上弦、开合盖、悬停标注、曲目切换 UI
```

数据流（每帧）：

```
输入事件 ─> interaction ─> mechanism.update(dt)
                              │ 输出：滚筒角度、钥匙/风扇角度、盖子开合、拨动事件列表
                              ├─> audio.trigger(tooth, time)      （按事件精确调度）
                              └─> render.update(state) ─> vgpu frame
```

**唯一事实源**：曲谱 `Song` 同时决定凸点几何位置和拨动事件，凸点与发声来自同一份数据，保证同步。

## 3. 模块设计

### 3.1 Blender 模型管线（`blender/`）

- `build_musicbox.py`：纯脚本建模，可重复执行。命令：
  `/Applications/Blender.app/Contents/MacOS/Blender -b -P blender/build_musicbox.py -- --out public/musicbox.glb`
- 生成的对象（名称即部件 ID，渲染与拾取都依赖这些名字）：

| 对象名 | 说明 | 材质 |
|---|---|---|
| `case` | 木盒箱体（倒角、内衬） | 胡桃木 + 内衬绒布 |
| `lid` | 盒盖，枢轴在后缘铰链处 | 胡桃木，盖内镶嵌装饰 |
| `glass` | 机芯上方的玻璃隔板 | 玻璃（半透明） |
| `bedplate` | 机芯底座 | 黄铜（拉丝） |
| `comb_base` | 钢齿梳的根部（齿本身程序化） | 钢 |
| `cylinder` | 滚筒本体（凸点程序化） | 黄铜（抛光） |
| `cylinder_bracket` | 滚筒支架 | 黄铜 |
| `spring_barrel` | 发条盒（含齿圈） | 黄铜 |
| `spring_coil` | 可见的发条卷簧 | 蓝钢 |
| `gear_train` | 传动齿轮组 | 黄铜 |
| `governor` | 调速风扇（空气阻尼叶片 + 蜗杆） | 钢 / 黄铜 |
| `key` | 底部上弦钥匙（蝶形） | 黄铜 |
| `felt` | 底座毛毡 | 毛毡 |

- 材质：Blender 程序化节点生成木纹、拉丝纹理，烘焙为 baseColor / normal / metallicRoughness 贴图（1024²），随 glb 一起导出。
- 每个动态部件的**原点设在其旋转轴上**，并以 glTF extras 记录 `axis`（局部旋转轴）、`ratio`（相对滚筒的传动比）。
- 导出时同时写入 `public/musicbox.meta.json`：滚筒半径、长度、轴心位置，钢齿根部位置与宽度、齿数，供程序化几何对齐。

### 3.2 glb 解析（`src/gltf/`）

- 只支持本项目需要的子集：单 buffer、`POSITION / NORMAL / TEXCOORD_0 / TANGENT`、`uint16/uint32` 索引、PBR metallicRoughness 材质 + 嵌入的 PNG/JPEG 贴图、节点层级、extras。
- 输出 `LoadedModel { parts: Map<name, { geometry, material, localMatrix, extras }> }`。
- 遇到不支持的特性直接抛出带说明的错误（如“不支持多 buffer”），因为 glb 由我们自己的脚本生成，不需要兼容其他来源。

### 3.3 曲谱与编曲（`src/songs/`）

```ts
interface Song {
  id: string; title: string;
  bpm: number; beatsPerRevolution: number;   // 滚筒转一圈对应的拍数
  notes: { beat: number; midi: number }[];
}
```

- **钢齿音阶**：18 齿，固定一套音高（以 C 大调为主、含常用变化音，覆盖约两个八度，具体在实现时根据 3 首曲子的音域确定并写为常量）。
- `arrange(song, combPitches)`：把每个音映射到钢齿编号；若音不在梳中，移八度后再找，仍找不到则在构建时报错（曲谱是静态数据，测试会覆盖）。
- **同齿冷却**：同一钢齿相邻两次拨动间隔必须 ≥ 120ms（真实八音盒的齿需要恢复时间），违规在测试中报出，由改编曲谱解决。
- 每首曲子恰好占滚筒一圈，循环播放。

### 3.4 机械状态（`src/mechanism/`）

纯逻辑模块，无 GPU / 音频依赖，便于测试。

- **发条**：`tension ∈ [0, 1]`。上弦：钥匙每转一圈 `tension += 0.1`，上限 1。放弦：滚筒每转一圈消耗 0.3 tension（满弦约可播 3 圈多一点）。
- **调速器**：目标角速度 `ω₀ = 2π · bpm / (60 · beatsPerRevolution)`。`tension > 0.15` 时恒速 ω₀；低于 0.15 时 `ω = ω₀ · smoothstep(0, 0.15, tension)`，模拟发条将尽的渐慢；tension 为 0 时停止。
- **盖子**：开 → `running = true`；合 → 立即停（真实八音盒的盖子会压住调速风扇的止动杆）。盖子开合动画 0.6s，缓动。
- **拨动检测**：每个凸点有角度 θᵢ 和钢齿编号。每帧从 `angle_prev` 到 `angle_now`，找出越过拨动角 θ_pluck 的凸点，按线性插值算出精确越过时刻，产出 `PluckEvent { tooth, time, velocity }`，velocity 与当前 ω/ω₀ 成正比（慢速时音量略小）。
- **派生角度**：发条盒、齿轮、风扇角度由滚筒角度乘以各自 `ratio` 得到（风扇转得很快，动态模糊感由着色器的叶片拖影近似）。钥匙经棘轮连接发条芯轴，**只在上弦时转动**，播放时保持静止，与真实结构一致。

### 3.5 程序化几何（`src/geometry/`）

- **钢齿梳**：每齿是一个细长盒体，按 meta 里的根部位置排列；齿长由音高推算（长度 ∝ 1/√f，再归一化到合理范围），低音齿根部背面附加铅块配重（真实八音盒的做法，可提升写实感）。用实例化绘制：一份齿网格 + 每实例 `{offset, length, toothIndex}`。
- **凸点**：一份小圆柱网格（尖端略倒圆）+ 每实例 `{θ, z（对应钢齿横向位置）}`，在顶点着色器中绕滚筒轴放置；跟随滚筒旋转由 uniform 中的滚筒角度完成，不在 CPU 每帧改写。换曲时重写实例缓冲。

### 3.6 渲染（`src/render/`，vgpu + WGSL）

- **通道顺序**：
  1. 阴影通道：主光（暖色平行光，模拟台灯）深度图 2048²，PCF 软阴影。
  2. 主通道：HDR 目标（`rgba16float`）+ 深度，4×MSAA；绘制所有部件。
  3. ID 通道（仅在指针移动时）：`r32uint` 部件 ID，读回 1 像素用于悬停拾取。
  4. 后处理：ACES 色调映射 + 轻微暗角，输出到画布。
- **着色模型**：GGX 微表面 BRDF（metallic/roughness），法线贴图；环境光用**程序化的暖色室内环境**（在着色器中用解析的天光 + 地面反射近似，并预计算一张小型辐照立方体贴图做漫反射），黄铜和钢的反射才有层次。
- **玻璃**：最后单独绘制，开启混合，菲涅耳增强边缘高光。
- **钢齿振动**：每齿一个 uniform 槽位 `{pluckTime, amplitude}`；顶点着色器按 `y = A · e^{-t/τ} · sin(2π f_vis t) · (x/L)²` 弯曲齿尖，f_vis 是缩放到肉眼可见的视觉频率（高音齿更快、衰减更短）。被拨动时凸点“推起齿尖再释放”的瞬间也由同一公式表现。
- **相机**：`vgpu/scene` 的 `orbitRig` + `smoothRig`，限制俯仰角与距离，默认 3/4 俯视角对准机芯。

### 3.7 声音（`src/audio/`）

- Web Audio；首次用户手势（打开盒盖或上弦）时创建 / 恢复 `AudioContext`。
- **钢齿音色**：每个音由 4 个正弦分音叠加，频率比约为 1 : 2.76 : 5.40 : 8.93（悬臂梁振型比例，带来金属感），高分音衰减更快；起音 2ms，指数衰减时长随音高（低音约 3s、高音约 0.8s）。
- **木盒共鸣**：全部音符汇入一条总线 → 两个峰值滤波（约 250Hz、1.2kHz）→ 短卷积混响（程序生成的脉冲响应，约 0.6s）→ 总音量。
- **调度**：`PluckEvent.time` 换算到 `AudioContext.currentTime` 后用 `start(t)` 精确调度，并带约 30ms 的前瞻，使画面和声音对齐。

### 3.8 交互（`src/interaction/`）

- **视角**：左键拖动环绕，滚轮缩放，双击复位。
- **上弦**：在钥匙上按下后拖动，按钥匙轴旋转（只能顺时针，带棘轮咔哒声，用短促的合成噪声脉冲）；拖动钥匙时禁用环绕。
- **盒盖**：点击盒盖开 / 合。
- **悬停标注**：ID 通道拾取部件，在指针旁显示 DOM 小卡片：部件名 + 一句话作用（如“滚筒：表面的凸点就是乐谱，转动时依次拨动钢齿”）。凸点和钢齿也可悬停，钢齿显示音名。
- **曲目切换**：右上角极简下拉。切换时自动合盖停转 → 凸点重排 → 用户再开盖播放。
- **状态显示**：左下角一个细的发条张力指示条。

## 4. 错误处理

- 浏览器不支持 WebGPU 或 `init()` 失败：显示说明页（推荐浏览器版本），不白屏。
- glb / meta 加载或解析失败：显示错误面板，含具体原因。
- `AudioContext` 被浏览器阻止：首次用户手势时再恢复；画面照常运行。
- 设备丢失（`device.lost`）：提示并提供“重新加载”按钮。
- 曲谱错误（音不在梳中、同齿冷却冲突）：在单元测试和开发模式启动时报出，不在运行时静默处理。

## 5. 测试

- **单元测试（vitest）**：
  - `songs`：每首曲子所有音都能映射到钢齿；同齿间隔 ≥ 120ms；每首恰好一圈。
  - `mechanism`：恒速阶段 ω = ω₀；发条将尽时单调减速至停；拨动检测在大步长 dt（如 100ms）下不漏事件、事件时间精确到插值；合盖立即停止。
  - `gltf`：用 Blender 生成的真实 glb 作为测试夹具，校验部件名齐全、顶点 / 索引数量、extras 存在。
  - `geometry`：凸点实例数量 = 曲谱音符数；齿长随音高单调递减。
- **渲染冒烟测试**：`vgpu/mock` 下构建全部 draw / pass 并执行一帧，确保着色器与绑定无误；`npx vgpu check` 校验 WGSL。
- **人工 / 浏览器验证**：在应用内浏览器打开页面，截图检查画面；验证开盖、上弦、换曲、悬停标注；听觉确认三首曲子正确、渐慢效果自然。

## 6. 技术栈与项目结构

- Vite + TypeScript（strict）+ `vgpu`（含 `@vgpu/wgsl` 的 Vite 插件，用于 `.wgsl` 导入）+ vitest。
- 包管理：pnpm（与 vgpu 一致）。
- `npm` 脚本：`dev`、`build`、`test`、`model`（调用 Blender 重新生成 glb）。
- 生成的 `public/musicbox.glb` 与 `musicbox.meta.json` 纳入版本库，开发者不装 Blender 也能运行。

## 7. 实现顺序（概要，细节见实现计划）

1. 项目脚手架 + vgpu 跑通一个三角形。
2. 曲谱与机械逻辑（纯 TS，测试先行）。
3. Blender 建模脚本 → glb + meta。
4. glb 解析 + 基础 PBR 渲染静态模型。
5. 程序化钢齿与凸点，与滚筒对齐，振动着色。
6. 声音合成与调度同步。
7. 阴影、环境光、玻璃、后处理等写实化。
8. 交互：相机、上弦、开合盖、拾取标注、曲目切换。
9. 浏览器验证与打磨。
