# 八音盒（Music Box）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 浏览器里一个写实八音盒：上弦、开盖后滚筒转动，凸点拨动钢齿，钢齿可见振动并同步发出合成音，3 首曲目可切换。

**Architecture:** Blender Python 脚本生成静态部件 `public/musicbox.glb` 与对齐数据 `public/musicbox.meta.json`；浏览器端 TypeScript 按曲谱生成凸点/钢齿实例，用 vgpu + 自写 WGSL（PBR、阴影、HDR）渲染；纯逻辑的 `Mechanism` 是时间线唯一来源，同时驱动渲染和 Web Audio 合成。

**Tech Stack:** Vite、TypeScript（strict）、pnpm、vgpu（`vgpu`、`vgpu/scene`、`vgpu/mock`）、`@vgpu/wgsl`（Vite loader）、vitest、Blender 5.2.2（`/Applications/Blender.app/Contents/MacOS/Blender`）、Web Audio。

**Spec:** `docs/superpowers/specs/2026-11-06-music-box-design.md`

**vgpu API 查询：** 本计划只写到 vgpu 的入口名（`init`、`surface`、`target`、`geometry`、`draw`、`frame`/`frameLoop`、`texture`、`clock`、`orbitRig`/`smoothRig`/`perspective`/`viewMatrices`）。具体选项以已安装版本的文档为准：`npx vgpu docs find <name>`、`npx vgpu docs cat <topic>.md`；3D 场景先读 `two-pass-rendering.md` 与 `scene-composition.md`。

## Global Constraints

- 仅支持 WebGPU 桌面浏览器（Chrome / Edge）；不做 WebGL 回退、移动端适配、编曲器、采样音色。
- 坐标系：glTF Y 轴向上，单位米。滚筒轴沿 +X。
- 钢齿数 18；音高（MIDI，升序）固定为：`[57, 60, 64, 65, 67, 68, 69, 71, 72, 74, 75, 76, 77, 79, 81, 83, 84, 86]`（A3 C4 E4 F4 G4 G#4 A4 B4 C5 D5 D#5 E5 F5 G5 A5 B5 C6 D6），存于 `shared/comb.json`，Blender 与 TS 共用。
- 同一钢齿相邻两次拨动间隔 ≥ 120ms。每首曲子恰好占滚筒一圈并循环。
- 发条：钥匙每转一圈 `tension += 0.1`，上限 1；滚筒每转一圈消耗 0.3；`tension > 0.15` 恒速 ω₀，否则 `ω = ω₀ · smoothstep(0, 0.15, tension)`；0 时停。
- ω₀（圈/秒）= `bpm / (60 · beatsPerRevolution)`。
- 合盖立即停转；盖子开合动画 0.6s。钥匙只在上弦时转动，只能单向（棘轮）。
- 视听同步误差 < 16ms；目标 60fps。
- glb 部件名（即 `PartName`）：`case, lid, glass, bedplate, comb_base, cylinder, cylinder_bracket, spring_barrel, spring_coil, gear_train, governor, key, felt`。
- 生成的 `public/musicbox.glb` 与 `public/musicbox.meta.json` 提交进版本库。
- 每个提交信息末尾加 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。

## Review Focus

1. **长帧 / 切后台再回来**（dt 达数秒）：不得一次性爆发几百个拨动音；`Mechanism.update` 把单步 dt 钳制到 0.1s。→ Task 3 测试 `clamps huge dt`。
2. **播放中切换曲目**：旧曲子的振动和未发声事件不能残留；盖子自动合上，开盖前不出声。→ Task 3 测试 `setSong resets and stays silent`，Task 9 测试 `cancelAll stops scheduled voices`。
3. **满弦继续上弦 / 反向拧钥匙**：张力钳在 1，反向拖动不改变张力也不转动钥匙。→ Task 3 测试 `wind clamps and ignores reverse`，Task 11 测试 `ratchet delta`。
4. **窗口缩放 / 高 DPR 屏**：悬停拾取坐标必须按目标纹理像素换算，否则标注指错部件。→ Task 11 测试 `cssToTargetPixel`。
5. **音频未解锁（尚无用户手势）**：事件应丢弃而非排队，避免解锁时一齐响。→ Task 9 测试 `drops events while suspended`。

### Task 3: 机械状态

**Files:**
- Create: `src/mechanism/mechanism.ts`
- Test: `tests/mechanism/mechanism.test.ts`

**Interfaces:**
- Consumes: `Song`、`ArrangedPin`（Task 2）。
- Produces:
  ```ts
  const WIND_PER_KEY_TURN = 0.1, TENSION_PER_REV = 0.3, SLOWDOWN_TENSION = 0.15,
        LID_SECONDS = 0.6, MAX_STEP = 0.1;
  interface PluckEvent { tooth: number; pinIndex: number; time: number; velocity: number }
  interface MechanismState {
    tension: number; phase: number;      // phase：滚筒累计圈数，单调不减
    omega: number;                       // 圈/秒
    lidOpen: boolean; lidT: number;      // lidT ∈ [0,1] 动画进度
    keyAngle: number;                    // 弧度，单调不减
    time: number;                        // 机械时钟（秒）
  }
  class Mechanism {
    constructor(song: Song, pins: readonly ArrangedPin[]);
    readonly state: Readonly<MechanismState>;
    setSong(song: Song, pins: readonly ArrangedPin[]): void; // phase=0、合盖、lidT=0
    wind(keyDeltaRadians: number): void;                     // ≤0 忽略
    setLid(open: boolean): void;
    update(time: number): PluckEvent[];                      // 推进到绝对时间 time
  }
  function phaseAt(state: MechanismState, time: number): number; // 用当前 omega 外推/回推
  ```
- 拨动规则：pin i 的拨动相位为 `pins[i].beat / bpr`（取模 1）；`update` 中相位从 p₀ 增到 p₁ 时，所有满足 `k + pinPhase ∈ (p₀, p₁]`（k 为整数圈）的 pin 产生事件，`time` 由线性插值得到，`velocity = clamp(omega/omega0, 0.3, 1)`，按 time 升序。
- 每个 `update` 内部按 `MAX_STEP` 子步推进；但若 `time - state.time > 1`（切后台），先把 `state.time` 直接拉到 `time - MAX_STEP` 再推进（丢弃这段时间，不补发）。

- [ ] **Step 1: 写失败测试**（构造 bpm 60、bpr 4 的测试曲：ω₀ = 0.25 圈/秒，pin beat 0/1/2/3 → 相位 0/0.25/0.5/0.75）：
  - `constant speed`：tension 1、开盖、`update(0.2)` 逐帧到 2s，omega ≈ 0.25，phase ≈ 0.5
  - `no pluck when lid closed`：不开盖 update 到 5s，事件为空、phase 为 0
  - `pluck timing`：开盖于 t=0，一次 `update(1.1)`（大于 MAX_STEP，验证子步）返回 beat 1 事件，`time ≈ 1.0`（误差 1e-6）
  - `wraps revolutions`：运行 4.5s 得到 beat 0 的第二次事件（相位 1.0）
  - `slows then stops`：tension 0.2 开始运行，omega 单调不增，最终 omega === 0 且不再有事件；tension 不为负
  - `clamps huge dt`：运行中直接 `update(30)`，返回事件 ≤ 1 个
  - `setSong resets and stays silent`：运行中 `setSong`，`state.lidOpen === false`、phase 0，随后 update 无事件
  - `wind clamps and ignores reverse`：`wind(2π·20)` 后 tension === 1；`wind(-1)` 不改变 tension 与 keyAngle
  - `lid anim`：`setLid(true)` 后 0.3s lidT ≈ 0.5（线性进度，缓动在渲染端）
  - `phaseAt` 回推：`phaseAt(state, state.time - 0.05) ≈ phase - omega·0.05`
- [ ] **Step 2:** `pnpm test tests/mechanism` → FAIL。
- [ ] **Step 3:** 实现 `mechanism.ts`。tension 消耗 = `Δphase · TENSION_PER_REV`。
- [ ] **Step 4:** `pnpm test` → PASS；提交 `feat: mechanism timeline (spring, governor, lid, plucks)`。

**Interfaces:**

- `gltf/glb.ts`（纯 CPU，Node 可测）：
  ```ts
  interface MeshData { positions: Float32Array; normals: Float32Array; uvs: Float32Array;
                       tangents: Float32Array; indices: Uint16Array | Uint32Array }
  interface MaterialData { baseColorFactor: [number, number, number, number]; metallic: number; roughness: number;
                           baseColorImage?: Blob; normalImage?: Blob; metallicRoughnessImage?: Blob;
                           alphaMode: "OPAQUE" | "BLEND" }
  interface PartData { name: string; mesh: MeshData; material: MaterialData; matrix: Float32Array /*本地到父，列主序*/;
                       parent: string | null; extras: Record<string, unknown> }
  function parseGlb(buffer: ArrayBuffer): Map<string, PartData>;
  ```
  不支持的特性（多 buffer、sparse、非三角形图元、外部 uri）抛带说明的 Error。一个节点多图元时合并为一个 MeshData 仅当材质相同，否则命名为 `<name>.<i>`。
